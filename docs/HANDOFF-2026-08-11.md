### Traps that make a green run meaningless

These are not hypothetical; each one produced a false "pass" in recent history.

- **`nx test core` sets `passWithNoTests: true`.** Exit 0 does **not** mean tests ran.
  Nx also swallows the vitest reporter, so you see no counts. The only way to know the
  suite is live is to break something and confirm a non-zero exit.
- **Bare `npx vitest` from the repo root reports "no tests" for 175 files.** It picks up
  demo specs that fail to load without Nx's Angular setup. `--dir` and `--config` do not
  fix it. `nx test core` is the only valid runner.
- **A gate that passes is evidence of nothing** unless `--self-test` proves it can fail.
  Two gates were BLIND at the 14.0.0 release commit — passing while the thing they
  watched was broken. Both turned out to be real defects, not bad mutations.

## 3. What shipped in 14.1.1

Content is the audit release: retractions, naming cleanup, defects found while
auditing, and gates. Full detail in `CHANGELOG.md`, which also explains why a MINOR
carries a `BREAKING` section (14.0.0 was pulled; `13.x → 14.1.1` crosses the major
boundary, so no `^13.5.0` range resolves into the removals).

Two additions worth knowing about because they change how work gets verified:

**`spec-types` gate (new).** Spec files were typechecked by **nothing** —
`tsconfig.typecheck-all.json` excludes `**/*.spec.ts` and core's typecheck config
covers only `*.typing.spec.ts`. Vitest transpiles via esbuild, which strips types
without checking them. Consequence found in the wild: a test passed
`entityMap({ selectId, history })` after `history` was renamed to `recordHistory`, so
both arms of the test built an identical default tree and its assertion held
**vacuously**. Green suite, premise gone.

The gate is a **per-file ratchet**, not a clean check: turning it on cold reports 238
errors across 43 files, almost all test-idiom noise. Files may not get worse; a file
with no baseline entry must be clean. Pay it down with
`node tools/check-spec-types.mjs --update` (count may only decrease).

**Retention is now measured, not asserted.** `tools/bench-retention-arms.mjs` is
committed so every published figure has a runnable command.

```bash
node --expose-gc tools/bench-retention-arms.mjs <shape> <width> <steps> [norec]
#   shape: scalar | sameRow | diffRows | allRows | n<K> | mixed
```

At 50 entries over 50,000 rows, bit-stable across reps:

| what the writes touch        | retained                             |
| ---------------------------- | ------------------------------------ |
| scalar beside the collection | 0.300 MB                             |
| one row                      | **19.383 MB**                        |
| fifty _different_ rows       | **19.383 MB** — identical to one row |
| every row                    | **114.776 MB**                       |

Two facts that were wrong on every surface before this and are corrected now:

- `entries × width` is a **floor**, not the model. Its constant is **~8 bytes** (a
  64-bit pointer), not the ~10 previously published — which is why ST2029 said
  24.73 MB while the spike measured 19.58 MB, and nobody reconciled the two for two
  releases. The missing second term is **~40 bytes per _changed_ row**:
  `entries × (width × ~8 B + changedRows × ~40 B)`.
- `entityMap({ recordHistory: false })` makes retention **independent of collection
  width** — flat ~0.15 MB at 1k, 10k and 50k. It removes the width term rather than
  shrinking it. The old figures (0.18/1.25/5.61 MB) grew with width, which was wrong
  in kind, not degree.

A corollary worth carrying forward: **a large bulk operation is not inherently the
expensive history case.** One 400-row entry retains 0.434 MB.

## 4. The next release: read three documents, in this order

The plan of record is `docs/architecture/history-PLAN.md`
on `feat/position-attributed-history`. It declares itself the authority on ordering and
priority; when it is silent, the tie-break is
[`history-priority-hierarchy.md`](./architecture/history-priority-hierarchy.md).

1. **[`history-the-greenfield-target.md`](./architecture/history-the-greenfield-target.md)** — what is being built and why. Owns the derivation.
2. **`history-PLAN.md`** — 22 settled decisions, invariants A–I with required mutation proofs, phases with a falsification gate each.
3. **`history-current-state-gap.md`** — what exists in `packages/core` today. Point-in-time; invalidated the moment Phase 1 lands.

The objective, restated because it is easy to slide back into the wrong one:

> Make multi-position optimistic operations safely reversible without caller-authored
> compensation. **User undo/redo is a second consumer of the same mechanism**, not the
> goal.

This is observed rather than assumed: v3's `bulkPatch$` deliberately performs no
optimistic pre-write, because there was no way to reverse a wrong bulk apply.

`commit()` splits into **`seal()`** (capture the speculative set) and **`confirm()`**
(promote into confirmed history). That split is what dissolves the
rollback/prefix-closure collision — prefix closure constrains _confirmed_ history, and
a sealed-but-unconfirmed turn was never subject to it.

### Phase 0 is two disposable spikes, and either can send the design back

**0A — ownership attribution.** Can a stable ownership position be resolved at write
time for plain leaves, `entityMap`, `form()`, `status()` and `stored()` with **no
measurable cost when history is not installed**? Four benchmark arms; arms 1→2 isolate
the zero-when-unused cost and are what the gate depends on. Also prove `PositionId`
stability across `changeId`, _and_ prove the naive derivation fails.

Head start: `entityMap` already computes `${basePath}.${id}`, so `basePath` **is** the
ownership position, free. The risk concentrates on the other four.

**0B — rollback viability.** Six outcome cases in `history-PLAN.md` §0B. **Case 4
(structural collection mutation under a concurrent writer) must not be skipped** — value
snapshots cannot compensate `remove row at index 1` after a reorder, which is why
collection anchors moved into this spike rather than the last phase. A scalar-only spike
proves nothing about the primary use case.

### The evidence boundary you must not cross

The retention numbers in §3 measure **`timeTravel()`'s snapshot stack**. The proposed
turn store is a different data structure — one entry per attributed write, so a 400-row
operation is ~400 entries and is plausibly `O(entries)`, not `O(turns)`. **That has not
been measured.** Phase 2 carries a turns×rows matrix to measure it.

Turns are the retention unit **because they are indivisible**, an architectural
argument that needs no memory evidence. Memory limits decide how many turns fit, not
whether a turn can be cut apart. An earlier revision of the hierarchy doc claimed the
turn-based retention was "now measured" — it measured the wrong structure. Don't
re-derive that mistake.

## 6. Failure patterns from this session — expect to meet them again

Recorded because they cost real time and two of them shipped to npm.

**A correct fix placed where something downstream silently undoes it.** Three
instances, all found within an hour:

- `publish-all.sh` resolved `workspace:*` specs **once before** the publish loop, and
  `publish_package()` runs `nx build` per package, which regenerates the dist manifest
  and overwrote the resolution. The fix was present, documented, and had never once
  worked — **14.1.0 shipped broken because of it.** Now resolved after each build,
  immediately before `npm publish`, with an independent guard on the bytes being
  shipped.
- `release-claims` excluded only prereleases matching `v${current}-`, so the fix worked
  for 14.0.0 and the bug returned at the next release. Now excludes all prereleases.
- `angular-compat` matched `from '...'` with single quotes only against **minified**
  output (`from"./core/ng-forms.js"`), so its reachability walk never left the entry
  file — while advertising itself as transitive. Now 150 reachable files, not 16.

**Verifying the mechanism instead of the outcome.** The 14.1.0 publish dry-ran clean
and printed six successes; the packages were unusable. Only reading the **registry**
afterward caught it. For anything outward-facing, verify the artifact where consumers
see it, not the tool's own report.

**Blind global replaces.** A `map` → `asMap` sweep left `llms.txt` and the core skill
saying `asMap()` was _"renamed from `asMap()`"_ — renamed from itself. A later
`15.0.0` → `14.1.0` → `14.1.1` sweep rewrote freshly-written comments into false claims
about which version shipped a bug. Both caught, both the same hazard. Scope replaces to
the files you have read.

**Numbers changed without re-running them.** Retention figures were once "reconciled"
by picking the pair that had a published table, without executing anything. When
actually run, the original number was closer than the edit. If a figure changes, the
harness runs.

## 7. Conventions

- **No RFCs for our own work.** `TODO.md` holds decided-but-undone work; `docs/rfcs/` is
  an archive of decisions already taken, kept mainly for the options that were
  _rejected_ and why. An RFC is what an outside contributor writes.
- **Point-in-time documents get correction notes, not rewrites.** Dated audits under
  `docs/audits/<month>/` and research under `docs/research/` record what was believed
  then. Add a dated correction block; do not edit the original claim.
- **Commit messages say _why_.** Recent history is the model.
- **No Claude attribution lines in commits.**
