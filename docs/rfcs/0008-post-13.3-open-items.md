# RFC 0008 — Open items after the 13.3.x audits

**Status:** proposed · **Date:** 2026-08-04 · **Supersedes nothing**

Four audit rounds over the 13.3.x work (one verification sweep, three adversarial)
surfaced twelve open items. This RFC records the options considered for each, why
one won, and which release it belongs in. Every load-bearing claim below was
verified by running code, not by reading it — where a claim was checked, the
evidence is cited.

## Release split

| Release            | Contents                                                                                            | Rationale                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| **13.3.1** (ready) | The two shipped-13.3.0 defects + their follow-ons, all with proof-of-defect tests                   | Proven fixes only                                                                                        |
| **13.4.0**         | Dev diagnostics, `finalize()`, `stored()` as a real signal, marker write-through, `reload()` status | Behaviour changes; needs its own adversarial pass — see [RFC 0009](./0009-13.4.0-implementation-plan.md) |
| **Backlog**        | callable-syntax retirement, benchmark statistics, demo verification                                 | Non-shipping or undecided                                                                                |

The governing rule, learned the hard way this session: **do not bundle unproven
changes with proven ones.** Everything outside 13.3.1 is pre-existing,
demo-only, or an unresolved design decision.

## 1. `stored()` leaves are invisible to tree traversal — **and leak secrets**

Not one bug, two independent root causes. Both are needed for a full fix; neither
alone closes it (proven with a spike).

- **RC-1 (shape).** `createStoredSignal` returns `(() => sig())` with methods
  attached. It is neither `isSignal` nor `isNodeAccessor`, and _every_ traversal
  in the repo branches on exactly those two guards. Consequences: `tree()`
  omits a top-level stored leaf; `recursiveUpdate` silently drops a parent
  merge-write; and `applyState()` — the devtools replay path — **replaces the
  live signal with a raw string**, after which reads throw.
- **RC-2 (store/accessor duality).** `makeNodeAccessor` copies store properties
  onto the accessor while its call path closes over the _original_ store;
  `materializeMarkers` writes only to the accessor. **This affects every marker**
  — nested `status()`, `entityMap()`, `form()`, `asyncSource()` all emit raw
  markers into `tree()` today.

**Security consequence.** With an explicit `storage:` option, `unwrap` deep-copies
the storage object into the snapshot, enumerating unrelated keys. Verified:

```json
{ "settings": { "theme": { "key": "leaky", "options": { "storage": { "auth-token": "SECRET-JWT-abc123" } } } } }
```

That reaches `serialization()`, `persistence()`, devtools payloads and audit logs.
The default path is safe (`options` stays `{}` because `createStoredSignal`
resolves storage itself).

**Options considered (15).** Brand with `NODE_ACCESSOR_SYMBOL`; a new
`STORED_SIGNAL_SYMBOL`; a generic `LEAF_SIGNAL_SYMBOL` protocol; **make it a real
Angular signal**; a façade signal beside the stored one; duck-typing in traversal;
a `WeakMap` side table; **materialize write-through**; accessor get/set
descriptors; materialize before accessors exist; **dev-mode loud failure**;
type-level exclusion; docs-only; deprecate the marker; opt-in enhancer; plus a
one-line `finalize()` fix.

**Recommendation.** `13.3.1`: dev-mode loud failure in `recursiveUpdate` /
`unwrap` / `applyState` (~3h, zero production cost, converts a whole class of
silent failure into a console error), plus the `finalize()` one-liner — `tree()`
called before `tree.$` never finalizes and returns raw markers. `13.4.0`: make the
stored signal a real Angular signal (spike-proven, **zero changes outside
`stored.ts`**, because everything already handles `isSignal`), then materialize
write-through for RC-2.

**Runner-up:** the generic `LEAF_SIGNAL_SYMBOL` protocol — rejected at 2–3 days
across seven files, and third-party tree-walkers still break because they don't
know the symbol. Conforming to the protocol that already exists beats inventing a
second one.

**⚠️ Trap:** branding stored with `NODE_ACCESSOR_SYMBOL` is the obvious move and is
silently wrong. `unwrap`'s accessor branch iterates own enumerable keys and skips
functions, so snapshots would quietly become `{key, version}` instead of the value
— a silent drop converted into a silent wrong answer.

## 2. Two `stored()` signals on one key are independent

**Options (12):** nothing; **dev warning**; dev throw; interning; in-process
broadcast; `storage` events; re-read on visibility; per-key generation counter;
lint rule; branded keys; marker memoisation; opt-in `shared` option.

**Recommendation.** Dev-mode warning naming both call sites (2h, patch). Turns a
silent divergence into a five-second diagnosis and cannot break anyone.

**Runner-up:** interning — rejected because two `stored()` calls may carry
conflicting `defaultValue`/`version`/`migrate` with no correct merge, and a
string-keyed map can never be weak. **⚠️ Trap:** the per-key generation counter
puts a map lookup on `sig()`, the hottest path in the library, and makes a signal
read perform I/O.

## 3. `reload()` on corrupt data leaves signal and storage disagreeing

**Options (12):** nothing; document; clear on failure; quarantine; `onCorrupt`
option; extend `clearOnMigrationFailure`; re-persist default; **`reload()` returns
a status**; **document the `onError` recipe**; expose `lastError`; rely on
self-heal; add a `validate` option.

**Recommendation.** Document the `onError` recovery recipe (1h, patch) — the hook
already fires with `operation: 'read'`, so this is a documentation gap, not a code
gap. Then `reload()` returning `'ok' | 'default' | 'error'` in 13.4.0.

**⚠️ Trap:** "write the default back so they agree" is everyone's first idea, makes
the invariant true, and permanently destroys recoverable user data on boot.

## 4. `@signaltree/callable-syntax` mangles non-leaf calls

**The premise is falsified, not the implementation.** A type-aware transform
cannot be delivered to Angular apps. Verified against a real build:
`@angular/build:application`'s schema has no `plugins` option; the experimental
`codePlugins` passthrough runs _after_ Angular's compiler plugin has claimed every
`.ts` file — a probe plugin received **zero** of them; ngtsc's transformer list is
hardcoded; and ts-patch is inert in production because `program.emit()` is
bypassed under `isolatedModules` without sourcemaps.

Two further defects found: `/augmentation` globally augments Angular's
`WritableSignal`, **re-introducing exactly the `@ngrx/signals` conflict core
deliberately removed** (`types.ts:79-90`) — and it is unnecessary, since core
already types leaves as `CallableWritableSignal`. The README also claimed a missing
transform yields catchable runtime errors; it yields silent no-ops.

**Options (14):** type-aware transform; esbuild `codePlugins`; ts-patch; fork the
builder; **type-aware ESLint rule with autofix**; codemod-once CLI; method
denylist; explicit opt-in marker; syntactic subset; editor-only; type-level-only;
deprecate; nothing; rootIdentifiers-only fix.

**Recommendation.** Ship a type-aware ESLint rule — it gets the checker for free,
discriminates leaves via `.set`/`.update` presence (verified exact), runs in
`nx lint` and the editor, and `--fix` doubles as the codemod. Then deprecate
`/vite`, `/webpack` and `/augmentation` with the rule as the migration target.
README corrections landed already.

**Runner-up:** codemod-once — most robust thing that could work, but one-shot;
nothing stops the _next_ silent no-op. The rule subsumes it; it doesn't subsume
the rule.

**⚠️ Traps:** esbuild `codePlugins` reads like the modern answer and receives no
files — anyone reasoning without building loses a sprint. ts-patch passes dev
testing and silently stops transforming in production, which is worse than not
transforming at all.

## 5–6. Guardrails rule; literal-`*` field names — **fixed**

The `noSensitiveData` rule was never broken. `authToken` was optional and absent
from `initialState`, and **core silently discards writes to keys outside the
initial shape**, so no changed path was ever reported. Seeding it makes the rule
fire verbatim. The real lesson is the core gap: recommend a dev diagnostic
(ST2005) for out-of-shape writes in 13.4.0 — that silence is why this looked like
a guardrails bug.

The glob filter used a _substring_ test where the rest of the codebase uses
_segment_ semantics, so a field named `weird*name` was dropped. Now a shared
`isGlobKey()` used at all three sites, with tests.

## 7. Benchmark statistics and labeling

`mannWhitneyUTest` has no tie or continuity correction and hard-returns "not
significant" for n ≤ 20 — while the UI's slider allows 10. It doesn't abstain; it
asserts a false conclusion. Bootstrap CIs and Cohen's d are already computed and
correct, just not surfaced.

**Recommendation.** Grey out significance below n=21 with an explicit label,
surface Cohen's d, and **delete the standalone `signaltree-vs-ngrx-store` page** —
verified orphaned (no route, no reference), so it can only mislead someone reading
source. Tie/continuity correction as a fast-follow.

## 8–9. Browser verification

A CI-wired suite already exists at `scripts/playwright/route-smoke.spec.ts`
covering 8 routes with console-error and redirect assertions.

**Recommendation.** Add `/guardrails`, `/stored-versioning` and the realtime route
to its `ROUTES` array (three lines), then one content-level assertion for
`/guardrails` — a shell check passes even if every panel reads zero, which is
exactly the failure its config change addresses.

## 10–11. Guardrails rule bug; What's New gap

Rule covered above. For What's New: add the v10.3.3 entry, plus a light CI check
that the newest CHANGELOG version appears on the page — full parity checking
false-positives on deliberately grouped entries.

## 12. Assurance on self-written fixes

Three adversarial rounds each broke the previous round's fixes, every time with
the author's own tests passing.

**Recommendation.** Adopt three practices: **proof-of-defect** (every bugfix ships
a test verified to fail against the pre-fix code — this is what made the ng-forms
fix trustworthy); **commit the property/fuzz test** (the 137k-sequence state-machine
search that validated `writeGeneration` is the test that would catch regressions);
and **`npm deprecate @signaltree/core@13.3.0`** once 13.3.1 lands, since 13.3.0 has
two confirmed defects.
