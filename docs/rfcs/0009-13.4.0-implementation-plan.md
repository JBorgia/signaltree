# RFC 0009 — 13.4.0 implementation plan

**Status:** proposed · **Date:** 2026-08-04 · **Depends on:** [RFC 0008](./0008-post-13.3-open-items.md)

## Goal

Close the traversal gap that makes markers invisible to the tree's own snapshot
and write paths — including the case where it leaks unrelated storage contents
into serialized output — and land the diagnostics that would have surfaced it
years earlier.

**Amendment to RFC 0008:** that RFC put the dev diagnostics and the `finalize()`
one-liner in 13.3.1. They move here. 13.3.1 ships _only_ fixes with a
proof-of-defect test against shipped code; a new dev-mode warning is a behaviour
change (it can break a consumer asserting a clean console) and does not meet that
bar.

## Scope

**In:**

- W1 Dev diagnostics for silently-dropped traversal and out-of-shape writes
- W2 `finalize()` on the builder call path
- W3 `stored()` becomes a real Angular signal (RC-1)
- W4 Materialization write-through (RC-2) — fixes **all** markers, not just `stored`
- W5 `reload()` returns a status
- W6 Duplicate-key dev warning
- W7 `onError` recovery recipe + security note in docs

**Explicitly out** (each has its own decision to make first):

- callable-syntax retirement / ESLint rule — RFC 0008 §4, needs a product call
- Benchmark statistics and demo verification — demo-only, does not ship to npm
- `stored()` key coherence beyond a warning; `onCorrupt` policy options
- Any change to `NodeAccessor`'s public shape

## Semver: MINOR

Not a patch — W3 and W4 change observable output. Not a major — no documented API
is removed or re-signed; the changes make the tree behave the way its own
documentation already claims. Consumers relying on the _broken_ behaviour are the
compatibility risk, and W1 exists to make that loud rather than silent.

## Work items, in dependency order

Order is load-bearing: diagnostics first so the behaviour changes that follow fail
loudly rather than silently.

### W1 — Dev diagnostics (~3h) · do first

Three sites currently swallow a value that matched neither `isSignal` nor
`isNodeAccessor`:

| File             | Site                                                 | Today                        | Add                       |
| ---------------- | ---------------------------------------------------- | ---------------------------- | ------------------------- |
| `signal-tree.ts` | `recursiveUpdate`, after the `isNodeAccessor` branch | falls through, write dropped | dev error naming the path |
| `utils.ts`       | `unwrap`'s function-skip                             | key omitted from snapshot    | dev error naming the path |
| `utils.ts`       | `applyState`'s final `else`                          | **overwrites a live node**   | dev error                 |

Plus a diagnostic for writes to a key absent from the initial shape — the gap that
made the guardrails rule look broken for hours. Allocate the next free `ST20xx`
codes (audit the existing set first; `ST2001–ST2004` are in core, `ST2006` is used
by `history()`).

Guard everything with `ngDevMode` so production cost is zero.

**Verification:** unit tests asserting each warning fires, and asserting silence in
the happy path. **Risk:** low — additive, dev-only. A consumer asserting a clean
console may newly fail, which is the point; note it in the changelog.

### W2 — `finalize()` on the builder call path (~15min)

`tree()` invoked before `tree.$` is ever touched never finalizes and returns raw
markers. Every other entry point (`$`, `with`, `updateAndReport`, `batchUpdate`)
calls `finalize()`; the builder's own call path is the sole omission.

**Verification:** a test that calls `tree()` as the very first operation and
asserts real values. **Risk:** low.

### W3 — `stored()` becomes a real Angular signal (~4–6h) · RC-1

Replace `const storedSignal = (() => sig()) as StoredSignal<T>` with the real
`sig`: capture `sig.set`/`sig.update` first, override them with the persisting
versions, then attach `clear`/`reload`/`flush`/`key`/`version`.

**Contained to `stored.ts`.** Nothing else changes, because `unwrap`,
`recursiveUpdate`, `applyState`, `serialization`, `enterprise/path-index`,
`schema/matcher` and `ng-forms` already handle `isSignal`. This is the whole
argument for conforming to the existing protocol instead of inventing a marker
symbol.

**Observable changes to declare:**

1. `tree(bigPayload)` now **writes to storage** for every stored leaf in the
   payload. That is the fix, but someone may be leaning on the drop; the 100 ms
   debounce absorbs the burst.
2. Stored leaves become visible to `tree()`/`unwrap()`/`serialization()` — output
   shape changes for anyone snapshotting a tree containing `stored()`.
3. Equality divergence becomes observable: core leaves use
   `createEqualityFn(config.useShallowComparison)`; `stored.ts` uses bare
   `signal()` (`Object.is`). Already true, newly visible. **Decide whether to
   align** — recommend yes, using the tree's configured equality.

**Verification:** proof-of-defect tests for each of P1a/P1b/P1c from RFC 0008;
`applyState` no longer replaces the signal with a string; existing 72 stored tests
stay green. **Risk:** medium, well-contained.

### W4 — Materialization write-through (~1d) · RC-2 · highest risk

`makeNodeAccessor` copies store properties onto the accessor while its call path
closes over the original `store`; `materialize-markers.ts:255` writes only to the
node it walked. For a nested marker that is the accessor, so the store keeps the
raw marker forever.

Expose the store off the accessor under an internal symbol and write to both.

**This fixes every marker** — nested `status()`, `entityMap()`, `form()`,
`asyncSource()` all emit raw markers today and nobody has filed it. That breadth is
also the risk: `tree()` output changes shape for any consumer with a nested marker,
and snapshot tests across `packages/` will move.

**Do not** convert the accessor to get/set descriptors instead. It contradicts the
load-bearing `writable: true` comment in `makeNodeAccessor` (whose absence caused a
real reported bug: _"$.users.upsertOne is not a function"_) and puts a getter call
on every leaf read in a library that sells read performance.

**Verification:** a matrix test — every marker type × {top-level, nested} ×
{`tree()`, parent merge-write} — plus the security case (explicit `storage:` no
longer reaches the snapshot). **Risk:** high; budget time for snapshot churn.

### W5–W7 (~5h total)

- **W5** `reload()` returns `'ok' | 'default' | 'error'` (`void` → value is
  additive).
- **W6** Dev warning when a second `stored()` registers an already-registered key,
  naming both call sites.
- **W7** Document the `onError` recovery recipe for corrupt data, and publish the
  security note: anyone passing `storage:` explicitly _and_ snapshotting has been
  emitting that storage's contents. W4 fixes it; the disclosure is independent of
  the release.

## Breaking-change register

| Change                                          | Who notices                        | Mitigation                                        |
| ----------------------------------------------- | ---------------------------------- | ------------------------------------------------- |
| Stored leaves appear in `tree()` output         | anyone snapshotting                | changelog + W1 warning first                      |
| Nested markers emit values, not raw markers     | anyone snapshotting nested markers | changelog; arguably nobody depends on raw markers |
| `tree(payload)` writes stored leaves to storage | payload-restore flows              | changelog; debounce absorbs bursts                |
| New dev console output                          | tests asserting a clean console    | `ngDevMode`-guarded; changelog                    |

## Test strategy

Non-negotiable, given three consecutive audit rounds each broke the prior round's
fixes:

1. **Proof-of-defect.** Every fix ships a test _verified to fail_ against the
   pre-fix code — demonstrated, not asserted.
2. **Commit the property test.** The 137k-sequence state-machine search that
   validated `writeGeneration` becomes a committed test (bounded for CI runtime).
3. **Adversarial gate before publish.** An independent pass briefed to _break_ the
   release, not confirm it. Rounds 1–3 each found real defects the author's own
   tests missed; assume round 4 will too.
4. **Marker matrix** for W4 as described above.

## Sequencing

| Milestone | Contents     | Gate                                                 |
| --------- | ------------ | ---------------------------------------------------- |
| M1        | W1 + W2      | tests green; diagnostics fire on the known-bad cases |
| M2        | W3           | stored matrix green; adversarial pass on W3 alone    |
| M3        | W4           | marker matrix green; snapshot churn reviewed         |
| M4        | W5–W7 + docs | full suite, builds, doc gate                         |
| M5        | Release      | adversarial pass over the whole delta, then publish  |

Ship M1 alone if W3/W4 slip — the diagnostics have standalone value.

## Rollback

Each work item is an independent commit with its own tests. W4 is the one most
likely to need reverting on downstream feedback; keeping it a separate commit
behind M3 makes that a single `git revert` rather than an unpick.

## Open questions for the owner

3. **W4 scope** — fix all markers at once (recommended: the bug is generic), or
