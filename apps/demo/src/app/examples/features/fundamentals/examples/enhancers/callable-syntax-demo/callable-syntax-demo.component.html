Branches are callable. Leaves are not.

One fact explains the whole rule: only leaves are Angular signals. A branch is SignalTree's own accessor, so we own its call semantics and a call can mean “merge this”. We do not own a signal's: calling an Angular signal is a read , and it ignores arguments.

  • tree.$.user({{ '{' }} name: 'Bob' {{ '}' }}) — branch, partial merge ✅
  • tree.$.user(u => ...) — branch, updater ✅
  • tree({{ '{' }} ... {{ '}' }}) — the root, same shape ✅
  • tree.$.name.set('Jane') — leaf write ✅
  • tree.$.name('Jane') — leaf call ❌ compile error since 14.0.0

What changed in 14.0.0: that last line used to type-check and then silently do nothing. The build transform meant to make it real (@signaltree/callable-syntax) could not run inside an Angular app at all, and could not tell a leaf from a branch — so it also broke branch calls it rewrote. The package and the type overloads are both gone. Every button below writes leaves with .set() / .update() , which has always been the working form.
