Attach and detach scale connections at runtime. Each is an independent composite instance — its own connection status, ticket draft and save state — and every one of them lives in a single tree, sharing one history buffer, one DevTools timeline and one snapshot.

The instances are entities in an entityMap. Attach is addOne, detach is removeOne, get is byId, keys is ids. No detached trees, no per-instance enhancer chain.

Actions across every instance land in one buffer in the order they happened, so Undo unwinds the last thing the operator did — not the last thing they did to this card. That ordering is exactly what a detached tree per instance destroys.

Detach disposes what the instance owns

open feeds: {{ openFeeds() }} / instances: {{ instanceCount() }}

Each instance owns a simulated stream. A tap({ onAdd, onRemove }) on the collection opens it on attach and closes it on detach, so the two counters above cannot drift. Note the gap: clear() and setAll() do not fire onRemove — only removeOne/removeMany/removeWhere do, which is why "Detach all" uses removeMany.

The feed stays out of the undo stack

samples written: {{ samplesWritten() }} · history entries: {{ historyLength() }}

Readings live in a second collection declared entityMap({ recordHistory: false }). They persist and serialise like everything else, but never enter time travel — so a stream at 2 Hz does not bury the operator's actions, and undo does not rewind a weight.
