⚡ Enterprise Enhancer — Deprecated

⚠️ @signaltree/enterprise is deprecated as of 13.5.0

Use tree.updateAndReport(partial) and tree.onPathChange(fn), both built into @signaltree/core. They need no enhancer, add no bundle, and are faster than this package. This page is kept as an honest record of the API and of why it was retired. 

// Before
const tree = signalTree(state).with(enterprise());
const result = tree.updateOptimized(payload);
if (result.changed) sync(result.changedPaths);

// After
const tree = signalTree(state);
const changed = tree.updateAndReport(payload);
if (changed.length) sync(changed);

🎯 Why it was deprecated

The headline claim was inverted. This page previously claimed roughly 2-5x faster bulk updates. That was never measured against @signaltree/core, and it is backwards: updateOptimized() measures slower in every workload measured — about 7x at 2,000 leaves when a tenth of them change, and about 160x when all of them do compared with tree.updateAndReport(), with the gap widening as the tree grows. Core leaves already use deep equality plus a reference-equality short-circuit, so “only write what changed” is core behaviour for free — the diff engine pays O(state) to skip writes that were already no-ops. Use tree.updateAndReport(partial), which returns the same changed paths.

Known defect, not being fixed: updateOptimized() silently drops any write targeting an array — it reports changed: true and writes nothing. An array is one leaf signal, but the diff engine emits element-level paths the apply step cannot consume. Write arrays through the leaf (tree.$.users.set(next)) or use updateAndReport(), which handles them correctly.

⚡ Diff-Based Updates

Only update signals that actually changed. Rather than replacing a whole state slice on each update, the enterprise enhancer diffs and touches individual properties — complementary to granular approaches like @ngrx/signals patchState and entity helpers.

📊 Bulk Operations

Optimized for high-frequency updates (60Hz+). Real-time dashboards, data grids, and WebSocket streams benefit immediately.

🔍 Change Tracking

Detailed statistics for every update: total changes, adds, updates, deletes. Essential for monitoring and debugging.

✅ Use enterprise when:

  • You have 500+ signals in your state tree
  • Bulk updates happen at 60Hz+ frequency
  • You're building real-time dashboards or data feeds
  • You need enterprise-scale applications

❌ Skip enterprise when:

  • Small to medium apps (<100 signals)
  • Infrequent state updates
  • Startup/prototype projects
  • Bundle size is critical (adds ~2.4KB gzipped, approximate)

Lazy initialization: Zero overhead until first updateOptimized() call. Path indexing and diff engine only activate when needed.

API Reference

tree.updateOptimized(updates, options?)

Performs optimized bulk updates using diff-based change detection.

Options:

  • maxDepth?: number - Maximum depth to traverse (default: 100)
  • ignoreArrayOrder?: boolean - Ignore array element order (default: false)
  • equalityFn?: (a, b) => boolean - Custom equality function
  • autoBatch?: boolean - Automatically batch updates (default: true)
  • batchSize?: number - Patches per batch (default: 10)

Returns:

{
  changed: boolean,
  duration: number,
  changedPaths: string[],
  stats: {
    totalPaths: number,
    optimizedPaths: number,
    batchedUpdates: number
  }
}

tree.getPathIndex()

Get the PathIndex for debugging/monitoring. Returns null if updateOptimized hasn't been called yet (lazy initialization).
